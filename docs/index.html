Install

The Claude CLI has to already be on your PATH. The installer records where it found it.

macOS and Linux

Wrapper lands in ~/.claude-yolo/bin, PATH line appended to your shell profile.

curl -fsSL https://raw.githubusercontent.com/khanalsaroj/claude-yolo/main/install.sh | sh

From a clone, run ./install.sh. Pass --no-profile to skip the profile edit. Remove it all with ./uninstall.sh.

Windows

Wrapper lands in %USERPROFILE%\.claude-yolo\bin, prepended to your user Path.

Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
iwr -useb https://raw.githubusercontent.com/khanalsaroj/claude-yolo/main/install.ps1 | iex

From a clone, run .\install.ps1. Skip the PATH edit with -NoPath. Remove it all with .\uninstall.ps1.

Open a new terminal afterwards so the updated PATH takes effect.

Finding the real executable

This is the only part with any logic to it. Both wrappers try the same three things in the same order.

  1. 01

    CLAUDE_YOLO_ORIGINAL, if set

    Authoritative. A wrong value fails rather than quietly falling back to something else, which is what makes the test suite trustworthy.

  2. 02

    the cached original-path file

    Written next to bin/ at install time, holding wherever the installer found Claude.

  3. 03

    a PATH scan, skipping its own directory

    The self-heal case. Reinstall Claude somewhere else and the cached path goes stale, so the wrapper rediscovers it instead of breaking.

If none of those produce an executable file, the wrapper prints one line to stderr and exits 127, the conventional code for a command that was not found.

Environment variables

Four of them. Two exist mainly so the tests never touch a real install.

CLAUDE_YOLO_ORIGINAL
Forces the path to the real Claude. Authoritative, no fallback. default: unset
CLAUDE_YOLO_HOME
Install root for the wrapper and its cached path file. default: ~/.claude-yolo or %USERPROFILE%\.claude-yolo
CLAUDE_YOLO_PROFILE
Which shell profile the POSIX installer edits. default: picked from $SHELL (.zshrc, .bashrc, .profile)
CLAUDE_YOLO_REPO_URL
Where installers fetch wrappers from when they are not run from a clone. default: the GitHub raw URL for main

Tests, and nothing else

No build, no lint, no dependencies. The two platform wrappers are the whole product.

sh test/run.sh      # translation, stdio, exit codes
sh test/install.sh  # installed artifact and self-heal
./test/windows.ps1          # Windows wrapper
./test/windows-install.ps1  # installer, sandboxed

No test ever touches a real Claude install. CLAUDE_YOLO_ORIGINAL points at a fake claude that echoes its arguments to both streams and honours FAKE_EXIT_CODE.

Installs are sandboxed through CLAUDE_YOLO_HOME and CLAUDE_YOLO_PROFILE, so your actual shell profile and user PATH are never written to.

There is no runner and no filtering. Each file is a flat sequence of assertions. CI runs the sh tests on Linux and macOS, and the ps1 tests on Windows.

Questions

Does this change my Claude installation?

No. Nothing is patched, wrapped, or overwritten. A second script named claude sits earlier on your PATH and execs the real one.

What happens to my other flags?

They arrive exactly as you typed them, including quoting and spacing. Only a whole argument equal to --yolo is replaced, and the match is case sensitive.

Do interactive sessions still work?

Yes. Standard input, output, and error are inherited rather than redirected, so the terminal UI, colors, and prompts behave as if you had run claude directly.

What if I reinstall Claude somewhere else?

The wrapper notices the cached path no longer points at an executable and rescans PATH for a claude outside its own directory. No reinstall required.

Is skipping permission prompts actually safe?

That is between you and your filesystem. The flag lets Claude act without asking first, and giving it a shorter name does not make it less dangerous. Use it on a machine and in a directory you would not mind Claude having free rein over.

Stop typing the long one.

Two wrappers, under a hundred lines each, and no runtime beyond the shell you already have.
